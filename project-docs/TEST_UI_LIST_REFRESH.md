# UI List Refresh Test Notes

## UI-LIST-THUMB-01 / UI-LIST-THUMB-02

投稿一覧の進捗サムネイル表示を確認する。

- 一覧の進捗サムネイルが、別画像を貼ったような表示ではなく、1本の横長な密度棒グラフとして見えること。
- 上段の棒グラフに、未着手部分と塗り済み部分の色が同じ列内で反映されること。
- 下段の細い進捗ストリップが、塗り済みブロックの位置を補助的に示すこと。
- `progress xx%` が表示されること。
- `painted/total blocks` が表示されること。
- layer数が `1 user` / `2 users` のように表示されること。
- 親layerと追記layerがあるprogressMapでは、最後に塗ったlayer色がサムネイルに反映されること。
- 色は `progress-layer-colors.js` の共通ルールに従うこと。
- progressMapがあるversionでは、一覧専用のprogressMap描画が優先されること。
- progressMapがなくprogressImage.urlだけがあるversionでは、R2 PNGのimg表示へfallbackできること。
- progressMapもprogressImage.urlもないversionでは、一覧全体が壊れないこと。
- サムネイル列の高さが極端に大きくならないこと。
- PC表示で、版 / 難易度 / 作者 / 進捗 / 進捗サムネイル / コメント / 操作 の列が崩れないこと。
- スマホ幅で横スクロールせず、サムネイルが自然に折り返されること。

## UI-TREE-01 / UI-TREE-02

投稿一覧の分岐ツリー表示を確認する。

- 文字ツリー記号 `└` / `├` / `│` / `─` が通常表示に出ないこと。
- 親子関係はCSSの線だけで表現されること。
- 子versionの接続線が、直線だけでなく曲線に近いエルボー表示になっていること。
- ツリー線は薄すぎず濃すぎないグレーで、他列やサムネイルに重ならないこと。
- root行はBASE / 起点として表示されること。
- `root/a` は `1`、`root/a/b` は `1-2`、`root/a/b/a` は `1-2-1` の数字パス方式で表示されること。
- from表示も `from BASE` / `from 1` / `from 1-2` の数字パス方式で表示されること。
- branchPathやdisplayVersionは通常表示の主情報として出ないこと。
- branchPathやdisplayVersionが必要な場合はtitle属性などの補助情報に留まること。
- depthが深くなっても、難易度以降の列位置がずれないこと。
- DLボタンと追記投稿ボタンが右端の操作列に残ること。
- 中間履歴の+/-ガターと、版列のツリー線が混ざって見えないこと。

## UI-LIST-INTEGRATION-01

新サムネイルと新ツリーを組み合わせた一覧を確認する。

- 複数chartカードが並んでも、各カードのヘッダーとversion行の列位置が揃うこと。
- BASEのみのchartでも、サムネイルと操作ボタンが自然に見えること。
- 分岐を含むchartで、BASE / 1 / 1-1 / 2 の親子関係が参考画像に近い導線で読めること。
- completed/progress=100のversionは完成バッジが分かること。
- downloadBlocked=trueのversionでは操作列のDL不可表示が維持されること。
- collapsedByCompletionの中間履歴を展開しても、進捗サムネイル列が崩れないこと。
- 既存の初回投稿フォーム、追記投稿フォーム、DL、追記投稿、APIエラー表示が壊れていないこと。

## UI-FORM-SYNC-01

追記フォームの追記元表示を確認する。

- 追記投稿ボタンを押した後、追記フォームの追記元表示が一覧と同じ数字パス方式になること。
- 追記フォームに `ver4.0-a / root/a/b/a` のような古い通常表示が残らないこと。
- 追記元の補助表示が `from 1-2` のように一覧と一致すること。
- 追記投稿自体の送信処理、progressMap送信、progressImage送信が従来通り動作すること。

## GitHub Pages確認手順

1. `https://monsta-bms.github.io/bms-wip-charts/` を開く。
2. ブラウザのキャッシュを避けるため、ハードリロードする。
3. 投稿一覧で進捗サムネイルが横長の密度棒グラフに変わっていることを確認する。
4. 分岐ツリーで文字記号ではなくCSS線だけが表示されることを確認する。
5. 複数layerを持つ追記versionで、サムネイルの塗り色がlayerごとに変わることを確認する。
6. 追記投稿ボタンを押し、追記フォームの追記元表示が数字パス方式になっていることを確認する。
7. 初回投稿と追記投稿を1件ずつ実行し、投稿成功後の一覧再取得でUIが崩れないことを確認する。
